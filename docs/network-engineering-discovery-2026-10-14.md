# NetTool 网络工程规划：现状与演进建议

日期：2026-10-14。状态：调研建议，用户已选择企业办公室/园区为优先场景，实施范围待讨论；本文不代表已批准的新功能需求或完成的设计规格。

## 现状判断

现有规划已经覆盖项目、场景模板、IPv4/VLSM、VLAN、网关、DHCP、IP 台账、三运营商双网、跨网规则、维护记录和 Excel 交接。问题主要在工程流程的衔接：用户需要先在工具外完成需求分析、设备选择与连接设计，再将结果登记到工具中。

| 环节 | 已有能力与代码依据 | 值得补充的工程支撑 |
| --- | --- | --- |
| 现场需求 | 项目客户、位置、负责人、备注；`src/domain/projects.js` | 楼栋/楼层/区域、点位、业务分类、当前数量和增长要求 |
| 地址规划 | VLSM 按设备数、预留和网关计算；`src/domain/subnet-plan.js` | 将需求与已保存网段关联，需求变化后提示重新校核 |
| 设备管理 | IP 台账有设备类型、位置、MAC；`src/domain/projects.js` | 设备实体、接口与连接；设备和 IP 不必一一对应 |
| 网络结构 | `ConnectivityPanel.vue` 有固定双网示意图 | 随项目数据生成的拓扑；实际设备、连接、位置可追溯 |
| 接入与策略 | 线路参数、规则顺序、跨网地址/协议/端口校验；`src/domain/enterprise.js` | 更灵活的架构场景、业务访问矩阵、规则影响解释 |
| 方案检查 | 已有地址重叠提示、DHCP/静态冲突、VLSM 容量校验 | 端口、PoE、上联容量及跨对象一致性检查 |
| 交接 | 项目 Excel 八表、规划 JSON、维护记录 | 需求依据、设备连接清单、校核问题和验收对应关系 |

现有双网示意图的运营商、出口防火墙和网络层次写在组件模板中，根地址空间动态显示；它没有设备节点、接口或连线的数据模型。它适合作为架构说明，尚不能表达具体现场拓扑。

现有 VLSM 已经能按设备量计算容量；后续应复用，重点解决项目需求与计算结果之间的联系。现有校验也应复用，不重新实现另一套地址规则。

## 三条路线

| 路线 | 收益 | 局限与投入 | 建议 |
| --- | --- | --- | --- |
| 丰富模板和说明 | 更快创建常见方案，投入较小 | 固定参数仍需要人工适配；工程连接和容量依据仍缺少 | 作为配套完善 |
| 建立工程规划流程 | 从需求推导方案、解释容量、形成施工与交接资料 | 需要新增工程对象并兼容已有项目 | 推荐主线，分阶段落地 |
| 先建设自由拓扑画布 | 网络关系更直观 | 如果图形独立保存，会出现图、IP 台账和设备清单互相不一致 | 在工程对象建立后推进 |

## 推荐的使用流程

场地与需求 → 设备与连接 → 地址与访问策略 → 方案校核 → 交接与现场验收。

每一步可以单独编辑，已有项目可以继续使用原有地址台账。完成度来自具体缺项及校核结果；不能仅按表单是否填写推断方案是否可靠。

## 已选择的主场景：企业办公室与园区

用户已明确优先企业办公室/园区，覆盖楼栋、楼层、有线与无线、内外网。以下为该场景的具体设计建议：

- 现场结构：项目 → 楼栋 → 楼层 → 区域；弱电间或机柜关联位置。位置结构与业务网络分区分别维护，同一楼层可以承载多张网络，同一业务网也可以跨楼层。
- 业务需求：有线办公、无线办公、访客、服务器/打印、视频物联、管理；每类记录当前数量、预留、地址分配方式及必要访问关系，允许用户调整分类。
- 有线容量：统计实际接入点位，支持记录有线与无线终端的使用关系，避免同一终端被重复计入物理端口。设备上联、专用接口及复用接口分别计数。
- 无线规划：登记覆盖区域、客户端规模、并发假设、AP 点位及 SSID 与 VLAN 的关系。第一期记录需求和已确定点位；AP 数量/覆盖不能仅按面积自动判定，后续覆盖建议需有场景假设和勘测依据。
- 内外网：记录业务隔离要求、逻辑分区或物理隔离选择及跨网服务；三运营商双网继续作为一种模板，普通办公室可选择单出口等结构。
- 交付资料：从区域需求表、网段容量表和待补充事项开始，后续增加设备/端口连接表、拓扑及验收清单。

界面建议保留全局诊断导航，在项目工作台内提供项目概览与场地需求入口，再逐步扩展设备连接、拓扑及校核。概览优先说明终端规模、需求缺项和容量风险；地址规划与 IP 台账保持可直接访问。窄窗口下位置树可收起，不长期占用第三列。

### 1. 场地与需求

按现场组织楼栋、楼层、区域和弱电间，登记终端、AP、摄像机、服务器等数量及增长要求。业务要求包括是否隔离、需要访问的服务、是否需要冗余。

模板作为起点，生成前展示需求、假设与结果；用户确认后保存。重新生成应预览差异，保留手工编辑和现有设备登记。

### 2. 设备与连接

设备实体独立于 IP 台账：一台交换机可以有多个管理接口和地址，一台设备可以连接多张网络；配线架或线缆可以没有 IP。

从最小设备与连接清单开始，记录设备位置、角色、接口数量/速率、PoE 预算和连接两端。后续再按现场需要扩展机柜、配线架、光纤芯数与完整端口映射。

物理连接和逻辑关系分别表达。跨楼层连接、VLAN 承载和跨网访问可以从同一份工程数据查看不同视图；移动图形只改变布局。

### 3. 容量与方案校核

所有计算展示输入、单位、公式与余量；缺失参数显示“待补充”，不作为检查通过。以下规则是候选，需随第一期范围细化：

- 地址：需求、增长预留、网关地址与已有 VLSM 规则关联；需求增加后提示容量变化。
- 接入端口：业务端口和预留端口，与设备可用接口比较；上联占用及电口/SFP 复用需按实际设备记录。
- PoE：同时检查单口供电能力和整机预算，区分设备端功耗与供电端预算，计入供电标准及线路损耗的依据。
- 上联带宽：按业务速率、并发假设和方向估算；主备链路不能简单相加，聚合链路也不能把总容量当作单条流的可用速率。
- 结构一致性：设备接口重复占用、连接端点不存在、位置关联失效、已引用网段变更等问题定位到具体对象。
- 策略：先提供规划规则的匹配解释；现场是否可达需要路由、NAT 和实际设备配置等证据，不能仅由规则表推断。

问题应给出依据、影响对象和修改入口。确定冲突、容量风险和资料缺项分别呈现，不生成缺乏依据的总分。

### 4. 拓扑与 UI

保留现有项目工作台，在项目内组织工程流程，减少新增全局菜单。概览展示需求规模、容量余量及待处理问题，而不只是网段和 IP 数量。

拓扑由设备与连接生成，选中对象显示对应位置、接口、地址和检查结果，并能跳回清单编辑。先支持自动布局、缩放和对象定位，再评估自由拖拽与复杂画布。

延续现有浅色/深色、大字模式、展开/折叠侧栏和窄窗口约定。图形之外保留可搜索的表格，状态同时用文字表达，确保大项目和键盘操作仍可用。

### 5. 交接与验收

在现有项目 Excel 基础上，逐步补充需求、设备、连接、容量计算与校核清单；文档同时记录版本、生成时间和估算假设。拓扑图导出属于后续范围选择。

验收项关联规划对象，并记录目标、时间和结果。复用 Ping、端口、DNS 等现有诊断，用户明确选定目标后运行。探测证据与人工规划状态继续分别保存；无响应不能证明地址可分配。

## 分阶段建议

| 阶段 | 具体产出 | 进入下一阶段前的检查 |
| --- | --- | --- |
| A：需求与容量 | 场地/区域、业务数量与预留；关联现有网段；地址和接入容量说明；需求资料导出 | 实际样例能解释“需要多少、为什么”，旧项目仍可读取与编辑 |
| B：设备与连接 | 设备实体、最小接口/连接清单、端口与 PoE 校核；自动生成拓扑 | 图、清单、地址引用一致，修改/删除影响可追溯 |
| C：方案与交接 | 业务访问矩阵、规则解释、方案修订对比、工程资料及验收关联 | 规划结论、估算和现场证据有明确来源；导入导出不丢关联 |

每阶段独立明确验收范围，不同时展开所有子系统。第一期建议从 A 开始，以一个真实工程场景走完需求录入、地址容量计算、修改后重新校核及交接。

例如三层办公楼、每层 40 个有线终端和 4 个 AP、预留 20%：如果这 44 个点位均为独立接入，采用向上取整的端口预留规则，每层需要 44 + 9 = 53 个业务/预留端口，上联端口另计。单台 48 口设备无法满足这个假设。无线客户端地址数量还需单独登记，AP 数量不能等同于无线客户端数量。

该示例说明计算方式，不是固定设备选型推荐。无线覆盖仍需现场勘测，PoE 和带宽仍需实际功耗与业务参数。

## 技术与兼容边界

- 沿用 Vue + Electron + SQLite。工程规则放纯领域模块，界面通过现有 runtime/IPC 保存；此方向不要求增加运行时。
- 新数据应使用稳定 ID 关联项目、位置、设备、接口及网段，避免按名称关联；已保存 IP 台账不能直接改成设备表。
- 实施规格需明确数据库迁移、旧 JSON/Excel 兼容、新字段往返及原子保存。旧项目不应被自动生成的方案覆盖。
- 图布局与工程数据分别维护。需求修改后提供影响预览，不静默重新编号地址、重分配设备或重写策略。
- 工程对象增加后需验证增量保存与界面渲染，延续本轮压力修复对历史负载和完整工作区读写的约束。
