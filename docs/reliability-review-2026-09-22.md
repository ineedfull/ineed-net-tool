# NetTool 功能与可靠性复核 · 2026-09-22

本轮在既有功能上补强通信判断、取消清理、故障导出及持续运行的页面资源开销。未操作现场工作区，所有通信测试使用本机回环服务与独立临时数据目录。

## 发现及处理

| 编号 | 问题 | 等级 / 分类 | 处理 |
| --- | --- | --- | --- |
| F-01 | 已取消任务仍可能进入域名解析或目标信息查询；解析完成后的监听与超时清理不明确 | 中 / 可直接修复 | 在任务入口、解析前后和信息查询前检查取消；解析监听与计时器统一清理 |
| F-02 | 零字节 Ping 回应缺少 RTT，被误判为无响应；回应数与耗时样本数混用 | 高 / 可直接修复 | 根据回包字段判断回应，耗时单独计数；未提供耗时显示为“—”，曲线不虚构 0 ms |
| F-03 | 扩展工具的数字参数接受布尔值或数组的隐式转换 | 中 / 可直接修复 | 仅接受非空数字或数字字符串，再校验整数和范围 |
| F-04 | 失败任务没有结果行时不能导出；保存失败缺少具体补救指引 | 中 / 可直接修复 | 已创建任务均可导出参数、错误和现有结果；保存失败明确提示先导出备份 |
| F-05 | 持续 Ping 同时渲染 500 行明细和完整原始输出，页面资源开销较高 | 中 / 可直接修复 | 默认显示最近 100 行明细、50 次原始输出，可切换全部；完整日志只在复制、导出或查看全部时格式化 |

关于之前“刚启动就停止仍启动底层进程”的描述：当前代码的进程和连接原语已经有取消检查，不能把该描述作为已复现的进程启动缺陷。此次补强的是上层调度与解析边界，并增加立即停止的回归证据。已经提交给系统的 DNS lookup 无法由 Node 强行撤销，但任务会及时结束等待，且不会用迟到的解析结果发起后续探测。

## 功能覆盖

| 范围 | 本轮验证 |
| --- | --- |
| 网段计算 | IPv4 / CIDR / 掩码、容量、广播、网关、子网编辑、独立计算、保存到项目 |
| IP 探测 | 原生回环、混合探测、并发上限、暂停继续停止；65,536 地址模拟与 8,190 条桌面结果回归 |
| Ping / 路由 | 零字节与常规 Ping、持续任务、原始输出、设备信息、原生回环 traceroute |
| DNS / 端口 | 10 类 DNS 记录、本地不存在/超时/取消、TCP 开放与拒绝、失败记录导出 |
| 测速 / 链路质量 / TLS | 本地 HTTP 下载及超时、TCP 采样统计、证书信任与期限、TLS 握手超时 |
| 数据保护 | SQLite 回滚、旧 JSON 迁移、损坏或未知版本拒绝、保存失败后可继续诊断、导出及重启恢复 |
| 界面 | 全导航、长诊断详情、浅深色、大字、小窗口、提示关闭和新增显示数量选择 |
| 项目工作台回归 | 台账、项目隔离、网段、Excel 往返及维护记录；本轮不扩展业务模型 |

## 验证结果

- Node 测试：86 / 86 通过，其中新增可靠性专项 8 项。
- Electron 全量：24 / 24 通过；随后显示数量优化涉及的 9 项回归全部通过。
- 生产构建和修改的通信模块语法检查通过。
- macOS arm64 应用包已生成于 `release/reliability-20260922/mac-arm64/Ineed Net Tool.app`，包内 Ping 日志、保存失败恢复和失败记录导出 3 项桌面回归通过。本地体验包未做发布签名；打包使用已安装的 Electron 43.1.0 运行时，避免重复下载等待。
- 快速启停：8 种任务各 10 次，共 80 次立即停止；均释放任务槽、只保存一次停止记录，无迟到事件。
- 保存失败：隔离桌面进程中注入写盘失败，确认错误提示、当前结果导出以及恢复写入后再次测试成功。
- 两分钟持续测试：200 ms 间隔、回环目标，600 发 / 600 收；保存明细和原始输出均限制为最近 500 条，重启内容一致。
- 显示优化后再测两分钟：599 发 / 599 收，默认最多渲染 100 行与 50 次日志；切换全部可见 500 条，默认视图下导出 TXT 仍为 500 条，停止及重启恢复通过。
- 新测试初次运行出现过测试夹具连接未清理和 Electron evaluate 不支持动态 import 的问题；均已修正夹具/测试方式后重新验证通过，不归为产品修复。

## 资源采样对比

两次均使用真实 Electron 窗口、本机回环、200 ms 间隔、持续约 120 秒，每 5 秒通过 `app.getAppMetrics()` 采样一次，共 24 次。CPU 平均值剔除首次采样，内存使用 working set。该数据为本机短时观察，不是严格隔离的性能基准，不包含独立系统 Ping 子进程。

| 项目 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 页面进程末次工作集 | 425.8 MiB | 247.2 MiB |
| 页面进程峰值工作集 | 433.4 MiB | 247.2 MiB |
| 页面进程平均 CPU 采样 | 1.75% | 0.83% |
| 主进程末次工作集 | 172.9 MiB | 173.3 MiB |

本次末次页面工作集约降低 42%。手动选择全部记录后开销会相应增加，但不会增加保留记录上限。原始采样见 `reliability-2026-09-22-soak.json` 与 `reliability-2026-09-22-soak-optimized.json`；可使用 `node scripts/verify-ping-soak.mjs` 重新验证优化后的版本。

## 数据与交付边界

- 不更改数据库格式、不迁移现场数据库、不删除用户配置或历史。
- 保持既有保留规则：历史为全项目合计最近 100 次任务；持续 Ping 明细与原始日志最多各 500 条，整次统计不截断。更长期的历史归档策略需要作为独立功能设计。
- 保存失败提供导出备份，不代表自动重试或自动恢复写盘已经实现。
- Windows / Linux 尚未真机验证；现场网络、长时间运行和公网测速不能由本机两分钟测试替代。
- 项目没有 Git 初始提交，所有已有内容均未跟踪；本轮未将整个项目提交。复核按 audit-fix 的分类、修复、测试顺序在当前会话执行；现有规划没有 phases/UAT 目录，采用直接代码检查和现有回归测试。
