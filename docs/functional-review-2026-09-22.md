# NetTool 全功能检查（2026-09-22）

首次检查确认了 3 项问题；随后经用户授权完成修复，并补充全页面布局检查。下面保留原始复现证据，当前修复结果见文末。没有修改数据库结构、删除现场配置或历史数据。

## 原始问题（现已修复）

### P2：大容量规划可以导出，但不能重新导入

- 位置：`electron/main.cjs:159`，`src/components/Planner.vue` 的 JSON 导入 / 导出。
- 导出接口允许最多 128 MiB；JSON 导入接口仅允许 2,000,000 字节。合法规划数据可能超过导入限制。
- 在当前打包版的隔离工作区构造一个 /19 网段、3,000 条设备登记，每条备注 700 个 ASCII 字符；通过现有数据校验并保存成功。
- 导出成功，文件为 **2,419,249 字节**；将同一文件导入时返回 `导入文件超过 2 MB`。
- 影响：较大的项目规划不能通过自身导出的 JSON 恢复或迁移；SQLite 原数据没有因此被删除。
- 建议：明确并统一规划文件导入导出容量边界；超限时在导出之前提示，或提供拆分方案；导入仍需结构、记录数、字段长度和项目归属校验。增加大容量往返用例。

### P2：设置与批量加入规划弹窗未正常滚动，内容越过底部按钮区

- 位置：`src/components/SettingsPanel.vue:58`、`src/components/SubnetCalculator.vue:106`、`src/styles/dialogs.css:53`。
- 两处都直接把 `fieldset` 作为弹窗的滚动容器。在当前 Electron / Chromium 中，声明 `overflow: auto` 后仍出现子内容越界，外层 `fieldset.scrollTop` 无法滚动。
- 设置窗口：920×620、大字模式下，内容区高 449px、滚动高度 550px；尝试滚到底部后 `scrollTop` 仍为 0。本地数据说明位于底部按钮区域，截图可见文字与按钮重叠。
- 批量加入规划：默认窗口，生成 12 个子网后打开保存弹窗。内容区高 709px、滚动高度 1,516px；`scrollTop` 仍为 0。最后一个名称输入框顶部约 1,526px，已超出约 832px 的弹窗底边，无法正常逐项检查或编辑。
- 建议：使用普通 `div` 承担滚动与高度约束，内部保留 `fieldset` 的禁用语义；标题和底部按钮固定。测试应覆盖滚动后末项可见、可编辑和不与底栏相交，而不只检查弹窗外框是否在屏幕内。

### P2：Ping 次数留空被当作持续运行

- 位置：`electron/network.cjs:16`、`electron/network.cjs:306`，`src/components/Diagnostics.vue` 的 Ping 次数字段。
- `Number('')` 得到 0，而 0 是持续 Ping 的合法值；界面清空次数后不会阻止启动。
- 已在当前打包版通过界面复现：清空 Ping 次数 → 开始探测 → 停止。保存的任务参数为 `count: 0`，状态为 `stopped`。
- 影响：本来只是漏填次数，却启动了无限次任务，需要用户主动停止。
- 建议：前后端均拒绝空白值，只有明确输入 0 才进入持续模式；覆盖空字符串、空格、0、正整数和非法数值。

## 修复与布局复核

- JSON 导入与导出统一为 128 MiB，继续执行原有结构、字段、记录数和归属校验。3,000 条长备注台账通过界面导出后导入另一项目，全部记录一致，原项目保留；超限文件和无效结构拒绝导入且不改已有数据。
- 设置与子网批量保存改为 `div` 独立滚动，内部 `fieldset` 保留禁用语义。1360×880 和 920×620 下测试 12 个子网，确认最后一个名称可见、可编辑，内容不覆盖固定底部按钮；设置覆盖深色、大字、小窗口。
- Ping 界面与通信入口拒绝空次数；明确输入 0 仍支持持续运行、停止及保存历史。公共整数转换同时拒绝布尔值、数组等非数字输入。
- 维护记录重新分配列宽，操作按钮在最小窗口内完整显示。长维护内容默认显示三行，可展开 / 收起全文，避免单条备注撑满屏幕。
