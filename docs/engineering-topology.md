# 工程拓扑与端口 VLAN 配置

在项目工作台打开“工程拓扑”，或从“设备与连接”进入。拓扑直接读取同一项目已有的设备、接口和连接；点击设备、连线或下方接口按钮会打开原记录编辑。保存后重新生成图和校核，不需要同步另一份图形资料。

图中设备和连线可用 Tab 聚焦，按 Enter 或空格打开原记录编辑。键盘动作会阻止默认激活，避免弹窗打开后同一次 Enter 又触发关闭按钮。

位置筛选包含所选楼栋、楼层或区域的子级，并保留直接连接的边界设备（虚线边框）。孤立设备仍显示。图中每页最多40设备，跨页连接仍在下方连接清单中，接口、连接和问题列表均分页。窄窗口中可在图内横向滚动，保持节点文字的可读字号。连线只表示已登记物理连接，不执行探测。

## 登记端口逻辑配置

在原接口编辑窗口选择“逻辑端口模式”。“业务接入 / 上联 / 其他”描述接口角色；Access / Trunk 是独立的逻辑配置。

- Access：最多关联一个本项目业务网段，登记 Access VLAN。
- Trunk：可关联多个业务网段，允许 VLAN 使用逗号分隔，如 `20,30`。留空表示未知，填写“无”表示明确不允许任何 VLAN。
- 未登记模式、网段 VLAN、业务关联或对应 VLAN 参数，均保持待补充。VLAN 只能为1～4094整数，允许列表不得重复。

业务网段来自项目地址规划。应在所需路径涉及的接口上声明承载的业务；校核只检查每段连接两端显式声明的业务，不推测缺失的间接路径，也不推断交换机内部转发。例如办公网 VLAN20 经过两级交换机时，分别关联涉及的接入及上联接口；任一 Trunk 的允许列表缺20，会定位该接口并列出业务 VLAN 与关联连接。

## 阅读校核与交给现场验收

“配置风险”表示 Access VLAN 与业务要求不同，或 Trunk 缺少业务 VLAN。“待补充”表示依据不足，包括已声明业务但未登记连接。“登记参数一致”表示当前登记参数满足这些检查。

校核覆盖本项目全部接口，不受拓扑位置筛选影响。物理环路可登记和显示，但该报告不验证 STP、LAG、冗余、路由、隔离或现场连通性；没有设备自动发现、SNMP 或配置下发。

问题旁点击“建立验收检查”，会在既有“现场验收”中创建目标为该接口的人工检查项，保留当前要求。不会生成通过结果，也不会自动关闭整改。使用已有结果、整改和显式复验流程记录现场证据；修正接口登记后仍需独立验收实际配置。

## 保存与交接

SQLite 和 JSON 沿用现有项目保存方式；旧接口缺少逻辑字段时显示待补充。导入为新项目会重新生成接口、连接和业务网段 ID 及引用，不覆盖原项目。

项目页面的缓存宿主以项目 ID 为边界：同一项目内离开工作台再返回可以保留页面草稿；切换项目会释放旧项目页面及其嵌套缓存、事件监听和图形节点，避免连续切换累积保留旧工程界面。

当前动态 Excel 输出27表，保留原25表表头，追加“端口逻辑配置”和只读“VLAN配置校核”。旧5/8/12/16/21/25表继续导入；静态五表模板不变。输入字段、版本标记和错误处理见[工程 Excel 契约](engineering-excel-contract.md)。导入时重新计算派生报告，不能通过编辑报告表改变结果。

## 持续验收入口

`npm run build` 后运行 `node scripts/verify-topology-soak.mjs --out=/absolute/isolated/path --seconds=1200 --idle=180`。输出目录必须未被该脚本使用，包含独立 SQLite、原生窗口采样、真实 27 表 Excel 和重启比对证据。该入口仅操作登记工程资料，不启动网络扫描。运行使用可见桌面，保留相同 renderer 完成静置后才进行独立重启核对。

`--diagnostic-gc=1` 仅用于另一个隔离进程调查分配；报告明确标记不具备正式验收资格。强制 GC 结果不能替代同进程自然静置恢复。
