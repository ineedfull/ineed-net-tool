# 现场验收与交付

在项目工作台选择“现场验收”。这是人工负责的工程验收台账，不是自动认证或新的探测执行引擎。先添加检查项，明确关联目标、方法、单位和预期；再使用“记录结果”登记实际情况及人工结论。项目级检查无需先登记设备，首次保存才启用可选验收数据，旧项目不会自动添加数据。

## 检查与结果

目标可为项目、已登记设备、接口或连接。检查方法为人工、Ping、端口扫描、链路质量；关联设备界面同时展示区域和端点，直接入口可回到“设备与连接”。修改目标、方法或预期会增加要求版本；修改名称、负责人或备注不增加版本。旧版结果保留，但不能证明新要求。

结果只追加、查看，不提供覆盖编辑或删除。每条结果保存记录时要求、测量时间、登记人、人工结论、实际和备注。时间按产品集中格式显示为本地 `YYYY-MM-DD HH:mm:ss.SSS`，登记使用带毫秒的本地日期时间控件，导入导出保留原始时刻。

诊断方法需选择当前项目匹配方法、已经保存的终态记录。仅复制有界白名单快照，包括出处 ID、目标、任务状态、参数、开始结束时间、数值指标及错误说明；不复制原始日志或全部扫描行。任务 completed 不能自动视为人工通过；error / stopped 不允许登记为通过。旧记录缺少必要身份或时间等字段时可能无法引用，需重新执行对应诊断。原始历史最多保留 100 条，已保存快照不依赖历史继续存在；导入后的来源 ID 仅作出处，不绑定本机同 ID 记录。指标未知与明确 0 分别保留。

## 整改与状态

操作顺序：检查项 → 失败结果 → 登记整改 → 后续通过结果 → 选择复验闭环。可编辑尚未闭环的整改说明、负责人、计划日期和备注。闭环必须显式选择同项、晚于失败初测的当前版最新通过结果，不能仅勾选完成，也不能因新增通过自动关闭整改。已闭环记录保留失败与复验关联。

每项按当前版本最大序号结果判定：无结果或无法判定为“待验收”，失败为“未通过”，通过但有开放整改为“整改中”，通过且无开放整改才为“通过”。后来的失败覆盖先前通过；修改语义要求后须重新验收。整体有未通过或整改中为“存在风险”，有待验收或空清单为“待验收”，全部检查通过才为“全部通过”。这些状态由领域报告统一生成。

有结果或整改的检查项不可删除。验收清单及历史要求引用的设备、接口、连接不可静默删除；先处理关联，保留历史关系。界面保存失败保留草稿，重试不会重复追加；切换项目销毁未保存表单，避免串存。

## Excel 交付与限制

当前动态模板/导出为 25 张表：新增“验收清单”“验收结果”“整改复验”三张输入表和“现场验收报告”派生表。兼容旧 5/8/12/16/21 表；静态五表模板不变。填写说明独立“现场验收版本”标记为 1 或空。启用后须完整保留三张输入表和原工程输入表。结果和整改逐条保存，报告含全部历次要求、结果、引用快照及整改，不只最终结论。

导入先校验预览，确认后创建新项目，重建所有业务 ID 与目标引用，诊断出处 ID 保留。错误不会写入工作区，派生报告完全忽略并重算。真实文本/数字类型、公式及百分比格式限制详见[Excel 契约](engineering-excel-contract.md)。最多 500 检查项、2000 结果、1000 整改；快照最多 8192 UTF-8 字节、8 个指标。10 MiB 文件输入守卫不保证任意不可压缩的最大文本都可导入。

SQLite 版本、应用 ID、用户数据目录和设置/诊断保留规则不变。记录和 Excel 为人工交接内容，不承诺防篡改审计。估算、回环测试和人工台账不能代替现场标准认证；需由负责人核实现场设备、布线与业务。NetTool 当前仅 Electron，macOS 开发宿主、本机测试、安装包及其他系统分别验收，见[本轮验证记录](site-acceptance-verification-2026-10-27.md)。
