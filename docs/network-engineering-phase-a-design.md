# 企业办公室/园区规划 A：场地需求与容量

用户于 2026-10-14 授权按调研路线落地。本次实施阶段 A，后续设备实体、连线拓扑、PoE/带宽和验收关联按 B/C 阶段继续演进。

## 目标与行为

项目工作台增加“场地与需求”页签。旧项目仍从地址规划进入；打开新页签可以建立楼栋、楼层和区域，记录有线办公、无线客户端、AP、摄像机、服务器、打印机等需求。区域允许直接位于项目下，也允许位于楼栋/楼层下。

每条需求关联一个区域，名称、业务类型、当前数量（可留空待补充）、增长预留比例、每单位地址数、每单位接入端口数、静态/DHCP、已保存网段（可未关联）、备注。无线客户端默认每单位接入端口为 0；AP 默认为 1，不把 AP 数量当成客户端数量。同一终端有线无线需求由用户按实际使用关系登记，避免重复计入物理端口。

切换已保存需求的业务类型保留数量、增长预留和自定义单位/分配方式；使用明确的“采用类型默认值”操作才调整地址/端口单位与分配方式，数量和增长始终保留。创建时类型可初始化这三个相关默认字段，同样不清空已填写数量与增长。

每个区域可填可用业务接入端口总数（可留空）。该数由工程师扣除上联、不可用及复用接口后填写，第一期不虚构交换机选型。缺少容量、数量或网段关联以“待补充”表达；明确不足以“容量不足”表达。

需求预留数量 = ceil(当前数量 × 预留百分比 / 100)。地址需求 = (当前数量 + 预留数量) × 每单位地址数；端口需求同理。逐行显示公式，再按区域汇总端口、按网段跨区域汇总地址。不同区域共用网段只计算一次网关。网关按已保存的实际值占 1 个地址，与台账网关记录不重复相加；有地址需求但没有网关时作为规划缺项（单主机 /32 可不要求网关）。

比较总地址需求与 CIDR 可用容量；DHCP 需求与已配置池比较；静态需求与排除 DHCP 池及网关后的容量比较。设备需求是整体目标规模，不与 IP 登记条数简单相加。显示已有登记量作为参考，不能将探测结果作为空闲依据。未知数量不能成为“容量充足”。

需求变化立即重新计算，不改已有 CIDR/IP 分配。第一期支持区域和需求增删改、容量编辑、校核与工程资料 Excel 往返；引用对象删除必须提示并先处理引用，禁止静默破坏关联。编辑/保存遵循当前 busy 锁与失败时保留草稿；切换项目不得将草稿保存到另一个项目。

## 数据与接口

`project.engineering` 为可选对象：`{ version: 1, locations: [], demands: [], capacities: [] }`。

- location：`{ id, parentId, kind, name, note }`，kind 为 building/floor/area；楼栋在根，楼层隶属楼栋，区域可在根/楼栋/楼层下。
- demand：`{ id, locationId, name, kind, count, growthPercent, addressesPerUnit, portsPerUnit, addressMode, networkId, note }`。kind 为 wired/wireless/ap/camera/server/printer/other；count 是 null 或 0～1,000,000 整数；growthPercent 为 0～1000 整数；两个 perUnit 为 0～16 整数；addressMode 为 static/dhcp；networkId 为空或属于本项目。
- capacity：`{ id, locationId, accessPorts, note }`；每区域最多一条，accessPorts 为 null 或 0～1,000,000 整数。
- 每项目最多 500 个位置、1000 条需求、500 条容量。ID 不重复、长度不超过 100，无控制字符；名称 1～100，备注最多 1000。拒绝循环/层级不合规、跨项目网段引用、非法数字和未知版本。
- `src/domain/engineering.js` 负责常量、空结构、验证和纯计算。`validateEngineering(engineering, networks?)` 验证结构和可选网段引用；`engineeringReport(project, networks)` 返回需求/区域/网段计算结果及 issues；`remapEngineering(engineering, networkIds, uuid)` 重建导入 ID。
- 报告 issue 包含 severity（pending/risk）、code、message，以及可定位的 demandId/locationId/networkId。计算结果字段由领域任务产出后写入契约文档供 UI/Excel 使用。

## 持久化与兼容

工程数据随 projects.data 的 JSON 保存，SQLite user_version 仍为 1、工作区 version 仍为 2，不重建数据。工程子对象独立 version=1，旧项目没有该对象时视为未启用，不自动覆盖旧数据。

`validateProjects` 校验工程结构；`validateWorkspace` 校验网段关联。`projectImport` 重建位置、需求、容量与网络 ID，保持引用一致。已有网段 JSON 导入继续保留工程数据。

Excel 增加三张可选输入表“场地位置”“业务需求”“接入容量”，以及只读输出“容量校核”。用 L001/N001 等工作簿编号关联，不外泄/依赖内部 ID。提供表头、中文类型、冻结行、输入说明和必要选项。无工程数据的旧五/八表工作簿继续可导入；有工程数据时输入表必须完整；校核输出由输入重新计算，导入不能信任旧校核结果。校验失败不写入；导入创建新项目。公式、链接、富文本仍拒绝。

在原“填写说明”中用可见的“工程资料版本”标记区分已启用但尚无需求的空工程对象与未启用的旧项目。显式不支持的版本拒绝；没有标记但有新输入表数据时按版本 1 读取。没有标记/工程数据的旧项目保持工程属性不存在。

## UI 与验收

使用现有 DesktopDialog、FeedbackBanner、语义 tokens 与表格。显示空状态、新增入口、需求和区域容量、网段校核、可定位缺项；不增加全局菜单，不提供虚构覆盖率或总评分。浅色/深色、普通/大字、侧栏展开/折叠及窄窗口下可用。

自动化覆盖 40 终端 + 4 AP /20% → 53 端口，无线客户端不增加物理端口，共用网段聚合、DHCP/静态/网关边界、未知参数、编辑/删除引用、旧数据兼容、SQLite 重启和 Excel 完整往返。真实 Electron UI 从创建位置、需求到修改后重算、导出/导入、重启恢复。测试全部使用隔离数据，不启动现场网络扫描。
