# NetTool 可见压力与异常输入验收（2026-10-14）

本轮 macOS arm64 Electron 验收完成。修复两处重复传输历史的分配问题；最终可见负载 20.506 分钟加 182.896 秒同进程恢复、完整数据核对和重启检查通过。

## 确认问题与修复

### 规划保存重复返回全部诊断历史

原 `workspace:save` 返回 Store 的完整状态，项目和设置保存也会复制全部诊断结果到 renderer。App 规划保存仅使用项目、网段和当前项目，历史另由加载与任务终态刷新。因此这些重复回执没有界面用途，却显著增加压力下的临时分配。

真实扫描 4,096 个回环端口后，一次保存回执的 JSON 达 645,599 个字符；新增真实 Electron 回归先因回执过大失败。修复后回执只包含版本、项目、网段、设置和当前项目；Store 仍事务保存完整状态，不改变表结构、历史上限或数据目录。回归校验每份回执小于 4 KiB，8 次并发保存结果正确，重启后所有原诊断明细相等。实现位于 `electron/main.cjs`，回归位于 `tests/ui/workspace-save-payload.spec.js`。

### 任务完成重复加载全部旧记录

仅收窄保存回执后，较长负载中 renderer RSS 仍达到数 GiB。隔离实际 UI 诊断的堆快照显示，回收前约 234 MiB 的 JS 堆回到约 20 MiB，包含当前保留历史及正常代码/界面对象；没有用该主动回收结果冒充正式自然恢复。

原 App 每个任务终态都会 `runtime.load()` 获取所有旧记录；多个工具反复结束会不断复制整个历史集合。现在 `NetworkTasks` 在事务成功后，通过终态事件发送本次完整 `historyRecord`。App 合并最近 100 条记录，实时视图继续按 task ID 拒绝旧事件；失败写入只显示 `saveError`，不新增历史。记录不重复放进实时 task 元数据，规划回执也不覆盖新历史。表结构、完整明细与项目归属保持原约定。

新增 Node 回归先复现最终事件没有已保存记录、实时 task 保留冗余历史；真实 UI 回归先复现两次任务导致两次全量加载。修复后都通过，旧记录、新记录和重启内容一致。实现位于 `electron/network.cjs`、`src/App.vue`、`src/domain/task-events.js`；失败写入和原生完整结果均有回归。

### 压力脚本的界面与内存采集偏差

旧脚本后续轮次直接调用原生启动接口，未走 App 的 task ID 重置；界面因此可能保留首轮结果。现在每轮通过真实界面填写、启动六种任务，并检查可见视图的 task ID 与完成数属于最新执行。

旧脚本每轮把完整历史对象传回 Playwright，只为了检查长度。现在直接只读 SQLite 计数；需要完整验收时返回 JSON 字符串，减少测试序列化的额外临时对象。十万条历史的独立对照中，完整对象序列化比只返回长度产生更高 RSS；主动 GC 后两者 JS 堆都回到约 13 MiB。该主动 GC 对照只用于归因，正式恢复阶段不调用 GC，也不重载或重启页面。

修复前 `soak/`、`soak-ui/` 和 `soak-fixed/` 已主动停止，退出原因记录在 `intentionally-stopped-baselines.json`。它们只用于问题诊断，不作为通过的长跑。

## 最终持续负载与恢复

正式运行通过，证据目录 `soak-final/`。负载参数为 20.5 分钟、`--burst=2`：每轮 2,046 个回环地址与 2,049 个端口（含夹具端口）、DNS、HTTP 下载、链路质量、TLS；持续原生 Ping，并发保存 8 次项目和 1 次设置。包含扫描暂停/继续/停止、下载停止、DNS/HTTP/TLS 异常响应；设置保存竞争包含不同主题和大字值，实际外观矩阵由完整 UI 回归验收。

随后在同一宿主、同一页面做三个各 60 秒阶段：停止任务、切换空白项目释放实时视图、返回项目工作台。每轮只读 SQLite 计数并核对实际界面诊断计数，避免仅为了计数加载所有明细。负载结束时，还逐条对照实际历史组件和工作区快照。每个采样核对窗口标题/可见/未最小化、页面 timeOrigin/URL、桌面解锁状态及宿主后代进程。恢复采样结束后才单独重启验收数据，重启后的低内存不计入恢复。

```sh
npm run build
node scripts/verify-network-soak.mjs --minutes=20.5 --burst=2 --idle-seconds=180 --out=/fresh/evidence/directory
node scripts/verify-network-soak-history.mjs /fresh/evidence/directory
```

macOS 原生 footprint/锁屏采样使用 `NET_TOOL_SOAK_NATIVE_SAMPLE` 指定此次工作区的采样工具；未指定时仍核对 Electron 窗口、页面身份和进程 RSS。`--out` 目录使用独占运行标记，避免覆盖旧证据。

独立历史检查器只读隔离 SQLite，核对所有保留记录的任务身份、完整快照、结果序号/唯一目标/汇总、Ping 最近 500 条、项目/网段/设置、完整性和外键。最近 100 个任务的保留规则仍生效；总执行结果数量不代表全部旧任务无限保留。

## 最终结果与内存

最终执行 246 轮，1,477 个任务：1,276 完成、72 按计划停止、129 个预期坏响应；意外错误 0、页面异常 0。累计处理 930,722 条结果、下载 329.34 MiB、保存 2,214 次。原生 Ping 5,558 次均收到回应，保留最近 500 条明细和 500 条日志。

实际历史组件逐条匹配工作区快照；重启后项目、设置及历史相等。独立只读检查验证 100 个保留任务、62,043 条明细的任务身份、所有序号/唯一目标/汇总和快照，SQLite integrity 为 `ok`、外键错误为空。总执行量包括按最近 100 个任务规则淘汰的旧记录，不表示无限保存全部旧任务。数据证据：`soak-final/history-verification.json`、`soak-final/before-restart.json`、`final-summary.json`。
